# Lenovo переносится в общий pipeline через adapter

Stage 60 исследует переносимость архитектуры, а не объявляет Lenovo готовым брендом. **Общий pipeline сохранился: отдельный configuration-resolution слой пока не доказан необходимым.** После небольшого Lenovo adapter точная конфигурация извлечена для восьми из десяти неизменённых моделей; два монитора остаются unresolved. Это не восемь готовых карточек: текущая строгая readiness даёт **10/10 `not_ready`**, поскольку exact gallery и проверенная русская пользовательская инструкция отсутствуют. Исходный baseline и первый batch без adapter сохранены: baseline и все десять моделей завершились `error` из-за отсутствия official Lenovo dispatch. **Stage 60 audit PASS**: финальный полный regression и UI/Excel QA завершены. Этот статус относится к аудиту переносимости и безопасности configuration scopes, а не к production readiness бренда. Дата аудита — 7 октября 2026 года; Samsung baseline commit — `b985c28d8d209f190ce00acef31a467e9a191b2c`.

## Baseline выявил пробел маршрутизации, а Support дал конфигурацию

Контрольный артикул, full MTM и part number — **21ML005BUS**, machine type — **21ML**, marketing model — **ThinkPad T14 Gen 5 (Intel)**. Первоначальный штатный `run_once()` не менялся: job `error`, official pages/facts/photos/documents отсутствуют; dealer получил `dealer_url_needed`. Этот результат означает системный пробел official dispatch, а не отсутствие модели у производителя. Исходные доказательства сохранены в `baseline.json` и `baseline.sqlite3`; LG-oriented generic readiness из baseline не является критерием принятия Lenovo.

Последующее исследование обнаружило storefront redirect на family `LEN101T0089`, PSREF SPA shell и exact Support. Query variants: `site:lenovo.com "21ML005BUS"`, `site:psref.lenovo.com "21ML005BUS"`, `site:pcsupport.lenovo.com "21ML005BUS"`, `Lenovo "21ML005BUS" ThinkPad T14 Gen 5 Intel`. Это план discovery, а не доказательство выполнения каждого поискового provider. Support embedded `ds_productinfo` содержит Model/IDs и Description с Core Ultra 5 135U vPro, 16GB DDR5-5600, 512GB G4 Perf, Windows 11 Pro English, 5MP RGB+IR, Intel Graphics и 14 WUXGA. Наличие конкретных характеристик вместе с совпадающим полным MTM даёт конфигурационную связь; общий `ImageSrc` категории ноутбуков exact photo не доказывает. ([Lenovo Support](https://pcsupport.lenovo.com/us/en/products/laptops-and-netbooks/thinkpad-t-series-laptops/thinkpad-t14-gen-5-type-21ml-21mm/21ml/21ml005bus))

Baseline adapter probe сохраняет wireless с альтернативами Bluetooth для разных OS как `conditional_configuration`, а не единый confirmed fact. Manuals index содержит User Guide, Hardware Maintenance Manual, Safety/Warranty и Regulatory candidates; файлы и соответствие модели не проверены. Русская инструкция имеет статус **«Не проверена»**, а не «Проверена, не найдена». Exact gallery, проверенная инструкция, PSREF exact API и dealer cross-check остаются gaps. Adapter probe не подменяет исходный baseline run.

## PSREF различает платформу и MTM, а URL не подтверждает identity

Lenovo storefront, Support и PSREF имеют разные задачи. Региональный storefront может перенаправлять точный `/p/{article}` на family PDP либо категорию. Его JSON-LD mpn и embedded `$pdpAllData` полезны для discovery и family metadata, но не доказывают выбранную конфигурацию. Support catalog строит family → machine type, затем adapter проверяет response полного MTM. Сами catalog leaves machine type не являются exact configuration leaves. ([Официальный каталог](https://pcsupport.lenovo.com/api/products/us/en.js))

PSREF `Product` и family PDF описывают платформу; `Detail?...M={MTM}` предназначен для модели, но query parameter **не является evidence**. Исследованный detail JavaScript обращается к `/api/model/Info/GetInfoByKey` с ModelCode и `/api/model/Info/SpecData` с model_code; gallery/documents используют ProductKey. Anonymous auth issuance и прямые detail API в этом окружении вернули HTTP403; сохранённые ответы — HTML, не извлечённые exact JSON. Official search index позволил сформировать независимый dataset и увидеть Model heading, но runtime extraction не получил подтверждённый PSREF configuration payload. ([Detail implementation](https://psref.lenovo.com/assets/detail-DHRNokao.js), [Auth implementation](https://psref.lenovo.com/assets/auth-CmCWbT8o.js))

Family T14 PDF перечисляет несколько CPU, панелей, камер, батарей, цветов, network и storage options. Starting/approximate weight зависит от конфигурации; dimensions могут различаться. Эти сведения остаются capabilities/candidates. Даже точное `14 WUXGA` из Support не подтверждает автоматически яркость, gamut, touch или refresh rate конкретной панели. Support HDMI2.0b и family PDF HDMI2.1 представляют разные scoped observations; family запись не должна молча перезаписывать exact source. ([PSREF family PDF](https://psref.lenovo.com/syspool/Sys/PDF/ThinkPad/ThinkPad_T14_Gen_5_Intel/ThinkPad_T14_Gen_5_Intel_Spec.pdf))

Observed documentation endpoint — `/{country}/{language}/api/v4/contents/productmultlanguagelist` с pids/types/countries/language; наличие title или language selector не заменяет скачивание и проверку файла. User Guide, HMM, Setup Guide, Safety/Warranty и Regulatory Notice классифицируются отдельно. HMM и service procedures не являются пользовательской инструкцией и не попадают в description. Robots доступен, но exact relation через sitemap не установлена; отдельного успешного sitemap/JSON-LD exact configuration payload нет. ([Documentation UI script](https://pcsupport.lenovo.com/esv4/psp-documentation/app-983e57c667.min.js), [User Guide](https://support.lenovo.com/fr/fr/documentation/SG10265), [Repair article](https://support.lenovo.com/au/en/solutions/ht516591), [robots.txt](https://www.lenovo.com/robots.txt))

## Identity и scope предотвращают ложное подтверждение конфигураций

`family_model`, `generation`, `machine_type`, `exact_mtm`, `exact_part_number` и `regional_variant` сохраняют разный смысл. T14 Gen 5 — модель/поколение; 21ML — machine type; 21ML005BUS — полный конфигурационный код. Похожий MTM, общий prefix или platform TB370FU у планшета не заменяет исходный sales MTM. Region устанавливается из metadata, а не только suffix: **83EM00KVMX относится к Nordics**, не к автоматически предполагаемой Mexico. Region HTTP endpoint kz также не означает страну продажи. ([PSREF regional model](https://psref.lenovo.com/Detail/IdeaPad_Slim_3_15IRH8?M=83EM00KVMX))

Ручная отрицательная проверка обнаружила важную ловушку: Support вернул HTTP200 и echoed Model=`21MLZZZZUS`, хотя Description был только `21ML`. Старый `invalid_mtm_probe.json` фиксирует ошибочный pre-fix `exact_mtm`. Окончательный gate требует совпадения полного Model, минимум двух разных именованных конфигурационных полей в Description и исключает CTO/XXXX. Этот эвристический gate не равен независимому каталожному доказательству существования каждой возможной строки, но отвергает наблюдавшийся echo без характеристик. Post-fix test/QA должен подтвердить отрицательный сценарий; старый artifact не считается финальным успешным подтверждением.

Для каждого поля сохраняется `section → raw label → value`; mapping даёт русские canonical labels, а технические названия Wi-Fi/Thunderbolt/TPM сохраняются. `up to`, `starting at/from`, `optional`, `varies`, `depending`, альтернативы `or` и maximum/support labels уходят в candidate scope даже на exact page. Family storefront specs также не превращаются в confirmed product facts. CPU/GPU/RAM/storage/display/OS/camera извлекаются только в объёме доступного exact Description; полнота ports/wireless/battery/dimensions/weight/keyboard/color/accessories не предполагается по family. Размеры и вес используют общую модель товара/упаковки; starting weight не становится точным весом MTM.

Три проверяемых сценария представлены baseline exact Support, storefront family redirect и многоконфигурационным PSREF PDF. Дополнительная пара Legion сохраняет разные GPU: 83LY0066PB — RTX5050, 83LY00JCRK — RTX5060; это два отдельных MTM одной family. IdeaPad exact TN/8GB и family IPS/touch/up-to иллюстрируют опасность смешивания вариантов. ([Legion PB](https://psref.lenovo.com/Detail/Legion_5_15IRX10?M=83LY0066PB), [Legion RK](https://psref.lenovo.com/Detail/Legion_5_15IRX10?M=83LY00JCRK), [IdeaPad exact](https://psref.lenovo.com/Detail/IdeaPad_Slim_3_15IRH8?M=83EM007FLK), [IdeaPad family](https://psref.lenovo.com/Product/IdeaPad_Slim_3_15IRH8))

Добавлен US-region fallback; полное live-покрытие всех регионов и всех provider не заявляется.

## Решение об архитектуре ограничено наблюдаемой выборкой

Выборка доказывает, что Lenovo не требует отдельной системы с нуля: небольшой brand adapter и scope полей позволяют переиспользовать `Excel → discovery → identity → extraction → normalization → evidence → readiness → UI → Excel`. **Необходимость отдельного configuration-resolution layer не доказана**: восемь конфигураций разрешаются непосредственно официальным Support body. Два unresolved monitors показывают gaps discovery/extraction, а не доказанную потребность решать комбинации family options. CTO и более широкая monitor/region выборка остаются за пределами доказательства.

UI/Excel QA завершена: `qa_ui_excel.json` подтверждает HTTP200 для всех десяти карточек, русские canonical labels, сохранённые raw fields, отдельные configuration/document/photo candidates, отсутствие support/driver fields и ноль confirmed photos. Листы «Конфигурации-кандидаты», «Документы-кандидаты Lenovo», «Фото-кандидаты» и «Готовность Lenovo» отделены от подтверждённых фактов. В `field_coverage_audit.json` для каждой модели проверены все 15 полей: CPU, GPU, RAM, storage, display, ports, wireless, battery, dimensions, weight, camera, keyboard, OS, color и included accessories. `not_extracted` не заменён family options и не означает отсутствия характеристики у товара.

Текущий scope и visual_qa в `qa_ui_excel.json` включают HTML inspection и standalone visual QA. Offline Chromium в `render_ui.py` получил четыре screenshots: `ui_exact_overview`, `ui_exact_candidates`, `ui_monitor_overview`, `ui_monitor_candidates`. Read-only artifact-tool render реального `export.xlsx` дал `excel_readiness.png`, `excel_candidates.png`, `excel_laptops.png`; изображения проверены визуально. Длинные gaps переносятся, русские статусы читаемы. Внешние изображения при offline rendering блокировались, поэтому качество и соответствие фотографий этим QA не подтверждены.

Lenovo targeted tests — **13 OK**, shared search Stage54 — **43 OK**, structural checks — **18 OK**. Первоначальный targeted failure по листу candidates исправлен и остаётся историей. `regression_before.log` не является pristine regression исходного Samsung commit: запуск пересёкся с редактированием Stage60. Hash failures относились к новым изменениям до регистрации authorized-change manifests и не классифицируются как прежние дефекты; import failures Playwright/gspread относились к отсутствующим зависимостям окружения. `regression_verified.json` — preliminary evidence. **Окончательный release regression завершён: exit0, 1442 tests OK за 756.798 s** (wrapper elapsed 766.479 s), evidence — `regression_release.json` / `.log`. Stage 60 audit PASS присвоен после этого результата.
Staged `git diff --check` — **OK**; исходные bytes и SHA frozen dataset проверены. **Stage 60 audit PASS**, полный regression **1442 OK**, UI/Excel и визуальная QA завершены. Reviewed Stage 60 payload передан в commit/push; итоговый hash, `HEAD == origin/main` и clean working tree фиксируются отдельно в `git log`/`git show` и финальном сообщении после Git-проверки.
