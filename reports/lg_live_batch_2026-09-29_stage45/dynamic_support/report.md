# Stage 45 — проверка динамической секции LG P12ED

## Результат доступа

Проверена ровно одна навигация на наблюдаемую официальную страницу `https://www.lg.com/kz/support/product-support/cs-P12ED.USAR/` через существующий `census.browser_runtime.PlaywrightBrowser`. Лимит был объявлен заранее: 1 навигация, до 60 ресурсов, до 45 секунд, только `www.lg.com`. После первого ресурса браузер распознал страницу проверки (`challenge_detected`). Результат и счётчики сохранены в [browser_result.json](browser_result.json). Подтверждённая остановка `www.lg.com` записана в `data/lg_fetch_log.json`; повторов, другого браузера, обхода защиты и дополнительных запросов не было.

## Что удалось установить офлайн

Сохранённый исходный HTML Stage 44 (`official_support/001_824eccff12.gz`) содержит 32 упоминания `P12ED.USAR` в маршруте, заголовке, метаданных и данных оболочки, но **0** упоминаний `P12ED.NSAR` и `Russian`. В нём есть конфигурационный атрибут `data-retrievemanualsoftwarelistendpoint="/ncms/api/v1/support/proxy/retrieveManualSoftwareList?locale=KZ"` и карта API с `PSPPAGE=/ncms/api/v1/support/proxy/productSupportPage?locale=KZ`. Это адреса источников данных, а не сами данные конкретного товара.

Сохранённый JS-бандл Stage 44 (`official_support/003_9c4c67ba73.gz`) показывает, что клиентский компонент вызывает читающее Next.js server action `fetchProductSupportPageDataAction` с кодом из сегмента `cs-…`. Компонент берёт товарные поля из `productSupportPage`, а список документов — из `productSupportPage.manualSoftwareList.manualList`. Ссылка на файл в интерфейсе берётся из `fileUrl`; если его нет, код строит адрес по `fileName` и `gscsPdsOpenUrl`/`gscsDirectDownUrl`. Отображаемое имя берётся из `fileNamePrint` или `originalFileName`. Это объясняет, почему проверка одного исходного HTML не видит данные динамической секции. **Это вывод из сохранённого кода; фактический успешный ответ server action и DOM после его выполнения в этом запуске не получены.**

Три сохранённых прямых обращения Stage 44 к служебным API вернули ошибки параметров/прокси. Они не являются ответом действия страницы и не содержат `P12ED.NSAR`, списка руководств, языковой метки или URL PDF.

| Значение | Наблюдаемый источник в этом запуске | Статус |
|---|---|---|
| `P12ED.USAR` | Адрес и метаданные исходной страницы | Кандидат; не товарное поле |
| `P12ED.NSAR` | Ранее вручную замеченная ссылка регистрации; в сохранённом ответе её нет | Не извлечено автоматически |
| Список manuals и `Russian` | Предполагаемый результат `manualSoftwareList.manualList`; успешного ответа нет | Не извлечены автоматически |
| URL русского PDF | Нужна конкретная запись документа с `fileUrl`/`fileName` | Не получен; PDF не скачан и не проверен |

## Карточка и предел проверки

Строка P12ED в существующей партии `ae3d2cb381744ba8a811e54231233254` **не перезапускалась**, потому что новый источник данных не получен, а хост остановлен. Её сохранённые результаты не затронуты: support URL — кандидат; задание `needs_review`; карточка `not_ready`; подтверждённых характеристик, фото и руководства нет. Отсутствие этих данных в исходном HTML не считается доказательством отсутствия на отображаемой странице.

Остальные 11 строк также не запускались: условие пользователя «после успешной проверки P12ED» не выполнено. Критерии PASS сейчас **не достигнуты**. Для продолжения без сетевого обхода нужен сохранённый фактический ответ `fetchProductSupportPageDataAction` или DOM после его выполнения, а затем прямой URL русского PDF. Только после проверки содержимого PDF можно сохранить документ как support/manual evidence; характеристики и фото потребуют отдельных product/spec и photo evidence.
