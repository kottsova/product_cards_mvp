## Причины

- **P12ED:** официальный KZ support API и отображённая support-страница связывают `P12ED.USAR` с `P12ED.NSAR` для поддержки и русского руководства. Это не товарная страница точного комплекта. В API нет характеристик/галереи комплекта; `modelImagePath` ведёт к общей картинке категории кондиционеров, `csProductPageLinkStatus` равен `NOT_MATCHED`. Состав коммерческого комплекта, характеристики и фото из этой связи не следуют. Кандидат Sulpak сохранён, запрос к нему не делался: остановка Sulpak возникла ранее на другой странице.

Поле основной KZ-карточки `data-pim-sku` печатает `ON77DK.DRUSLLK.EEAK.KZ.C`, а основные RU-поля `data-adobe-salesmodelcode` и `data-adobe-salessuffixcode` печатают `ON77DK` и `DRUSLLK`. Два целых структурированных токена равны полному артикулу каталога после соединения; старое буквальное сравнение требовало точку и помечало обе страницы лишь как базовую модель. URL, search snippet, canonical URL и имена изображений не использовались как доказательство кода.
- **ON77 manual:** проверенный русский PDF называет семейство `ON77DK`, а фактическая RU-страница поддержки, открытая по ссылке с PDP, после редиректа печатает `data-product-id=ON77DK.DLVALLK`. Это другой суффикс. PDF остаётся сохранённым и проверенным по содержимому, но связь именно с `DRUSLLK` не подтверждена. Поэтому `done` не превращается в `export_ready`.
- **Аналогичный manual gap:** `RNC9.DRUSLLK` имеет точные PDP и проверенный русский PDF семейства. Сохранённая исследовательская страница поддержки Stage 43 печатает `RNC9.DEUSLLK`; точной связи инструкции с `DRUSLLK` в рабочем evidence нет. Появился честный пробел готовности. У ON77 прямой PDF-link тоже есть, но страница печатает другой суффикс. Проверка ссылок: [`manual_link_audit.json`](manual_link_audit.json).

## Правило identity

Код хранит ребро `source → represented model → relation → requested article` с типами `exact`, `component_of`, `family_of`, `regional_variant_of`, `support_for`, `unknown`. Для товарных полей точное совпадение получается только из **основного структурированного поля PDP**. Слитный код каталога равен двум целым токенам `model + suffix`; совпадение префикса или URL не повышает уровень. Страница поддержки подтверждает инструкцию, когда её содержимое связывает весь запрошенный комплект либо нужный вариант. Страница поддержки не подтверждает товарные характеристики и фото. Для фото/характеристик допускается точный PDP либо отдельно доказанная общность для семейства; в этой партии такого доказательства для P12ED нет. Сохранённые сырые факты, фото и PDF остаются доступными для аудита; готовность считает только evidence допустимого уровня. Если в каталоге записана лишь базовая модель без суффикса, отдельный региональный суффикс источника не объявляется кодом каталога.

Точные исходные поля и граф по всем 12 строкам: [`identity_graph.json`](identity_graph.json). Для P12ED снимок API №127, SHA-256 `214b5810fb3d7a65d79200642bd4a7e92b9aa8fd5a9b8b280c59e8445f22b94f`: `productSupportPage.manualSoftwareList.csSalesCode = P12ED.USAR`, `...modelList.csSalesCode = P12ED.NSAR`, элемент `manualList[2].fileNamePrint = Russian`, `fileName = MgwJVxEROplE6nOrxFymAA`. `fileUrl` в API равен `N/A`; фактическая прямая ссылка взята из отображённой support-страницы и уже сохранена в карточке как `https://gscs-b2c.lge.com/open/downloadFile?fileId=MgwJVxEROplE6nOrxFymAA`. Ранее проверенный PDF не содержит строки `P12ED`; его связь с системой установлена support page, PDF не использован для характеристик/фото.
