## Implementation

The existing browser-assisted strategy now has two explicit modes. LG eligibility accepts an actually completed safe GET with an ordinary available response and the expected generated query, without requiring a JS flag. Route action, query parameter and constants are checked against the saved request string; arbitrary URL construction is not permitted. Historical protection and foreign redirects still deny access.

LG used exactly `https://www.lg.com/kz/search?q=27ART10AKPL`. There were no input searches, fills or resubmits. Interactive mode is restricted to an already observed safe search page with undeclared query parameter/handler. Dreame used the previously observed `https://global.dreametech.com/search`, found one visible explicitly labelled search input, revalidated its form and submitted HHR12A once.

The worker exports a semantic projection instead of full DOM HTML: safe UI/form descriptors, local result links, limited Product/ItemList JSON-LD and Product microdata, protection/cookie indicators and metrics. No generated IDs, input values, storage, unrelated scripts/CSS/SVG or full page body are captured. The store applies a second schema whitelist. Existing Stage 5.1 candidate rules and structured target identity verification are reused.

Budgets: 120,000 bytes total, 12,000 bytes per fragment/descriptor, 100 fragments, 20 input descriptors; 200 admitted network requests; one context, two queries, six navigations, three targets, 60 seconds total, five seconds per operation and at most one idempotent retry. Excess projection/network has its own outcome. Images/fonts/media and downloads are blocked, CSS and necessary first-party scripts/XHR/fetch are counted and allowed within the cap.
