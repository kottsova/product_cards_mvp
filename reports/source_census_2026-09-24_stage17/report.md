### Adapter readiness criteria (identical for every wave, measured per family)

1. **identity_exact** — Exact identity: the adapter returns exact_variant only when the page's own code equals the catalog code including region/service suffix; base_code_confirmed or family_only otherwise.
2. **variants_positive_negative** — At least one positive and one negative (wrong colour/region/size/suffix) variant fixture per category in scope; the negative never becomes exact_variant.
3. **specifications** — Specifications extracted as name/value pairs, each with source URL and evidence; unit and value are not rewritten.
4. **gallery_complete** — The full gallery that belongs to this exact variant is captured; images of other variants, banners and icons are excluded with a recorded reason.
5. **documents_evidence** — A document is attached only from a direct link whose content or page names the exact model; regulatory papers are not instructions; absence is stated as a gap, not filled from a neighbour model.
6. **run_once_offline** — worker.run_once() replays a catalog row offline against saved fixtures and finishes done or needs_review with the expected reason for every fixture.
7. **checkpoint_resume** — The coverage executor saves a checkpoint per row, and a second pass over the same checkpoint makes no new calls and repeats no completed row.
8. **policy_fetch** — Every fetch goes through PolicyAwareFetcher (allowlist, redirect checks, budget, persisted log); a recorded 401/403/429/challenge stops the host across a restart.
9. **coverage_delta** — `python -m product_tool.coverage delta` against the pre-adapter plan shows the promised movement out of the wave's source statuses and no unit moving into ready_to_run without a positive fixture.

Razer stays out of every wave while its host is stopped (Stage 13 §1); Stage 12's Razer page data is not counted as evidence anywhere in the queue.
