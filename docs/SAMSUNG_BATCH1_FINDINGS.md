# Samsung: category list, selection rules, batches 1-2, the limited adapter and its place in run_once() (Stages 24-28)

Reports and evidence: `reports/source_census_2026-09-25_stage24/report.md` (batch 1) and `reports/source_census_2026-09-25_stage25/report.md` (adapter, correction, batch 2). Working rule: one product per category of the brand, in small batches; the rest stay queued (not cancelled); no bulk processing of catalog rows.

## Selection rules
- 31 catalog categories, 1182 rows. Home appliances: old models are looked for too (most of the catalog is old); no novelty is required. The "new models only" rule stays for smartphones, tablets and wearables; computers, TVs and other technology have no automatic ban on old models -- the concrete product and the exactness of its match to the catalog decide.
- Batch 2 rule (Stage 25): among catalog rows with a clean article and an exact page in the full official sitemaps (`kz_ru/vd-sitemap.xml`, `kz_ru/da-sitemap.xml`), the smallest SHA-256 of the article.
- Excluded: the N5300 TV (`UE43N5300AUXCE`); Galaxy Buds3 FE (no catalog row). The microwave `MS23K3614AK/BW` keeps its Stage 8.4-8.6 evidence and now also has its page saved.

## Official routes
Sitemaps list TV and appliance pages; phones and tablets are on the hubs `smartphones/all-smartphones`, `smartphones/galaxy-a`, `tablets/all-tablets` (the hub also embeds image URLs, which are not pages). A phone's photos are on its own `/buy/` page (the JSON-LD BuyAction target); the specification table is on the product page. Documents: links printed on the product page (`org.downloadcenter.samsung.com/downloadfile/ContentsFile.aspx?...&CDCttType=UM&ModelName=...`); the file name has a language token (`_RU_`, `_KK_`, `_UZ_`, `RUS`, `ENG`) that only ORDERS the requests: a file named `UZ` was a 206-page Russian/Kazakh manual.

## Correction (Stage 25)
Stage 24 wrote that the specification table is client-rendered and that a TV has one photo. Both were wrong. Product pages carry the table in static HTML (the `pdd32-product-spec` accordion: TV 117 items in 16 groups, vacuum 28, washer 85, phone 64, microwave 59) and the full gallery in the lightbox (`hdd02-gallery__popup-vertical-image`; TV 8 photos). The generic extractor gave 0 only because it looks for `dl/dt/dd` and Shopify gallery attributes.

## The adapter: `product_tool/adapters/samsung.py` (works on a fetched page; not wired into the worker)
- Identity: exact only by page CONTENT (JSON-LD sku/name or title = strong; the code only in the visible text = `text_only`); the URL never counts. Region/colour differences stay open (phone `INS`/`ZA` in the catalog vs `SKZ`/`DG` on the KZ page -> base model only).
- Specification table: every accordion item, grouped; an item without a title carries its group's value; nothing is invented.
- Photos: one asset once at its largest size; thumbnails (`-thumb-`, `104_104`) and 3D files (`.glb`, `.usdz`) are never photos.
- Documents, three separate facts: Russian by the text; tied to the product by the official page (`exact_page` when the page shows the full article); the exact model named inside (the catalog model, and separately the model the page's own link declares, including prefix and positional masks). No code equality (SC = VC, LS = S) is assumed. A file without extractable text is a manual check.
- Dealer fallback (`merge_dealer_fields`): a dealer value fills only a field the official page lacks, only on an exact model AND variant match, with its own source; it never replaces an official value and a differing dealer value is only reported. DNS knows only pre-verified URLs (none for Samsung), so it makes no request and produces the ready-to-ask dealer request.

## Stage 26: the adapter inside the ordinary worker path (`worker.run_once()`)
Report and evidence: `reports/source_census_2026-09-25_stage26/report.md`. Offline only: the eleven cards of batches 1-2 (one per category) were replayed on the saved responses; no real request was made.

- Code: `product_tool/adapters/samsung_source.py` (routes, page, buy page, instruction files, all through `PolicyAwareSession`: allowed hosts, redirect check, persisted stop log `<data dir>/samsung_fetch_log.json`, at most 7 requests per row), `product_tool/samsung_pipeline.py` (the Samsung stages of `run_once()`), `product_tool/samsung_readiness.py` (readiness with evidence levels), `product_tool/card_evidence.py` (structured evidence next to a card; open review items in `human_reviews`). `worker.py` only dispatches (`SAMSUNG_BRAND_ALIASES`, `samsung_adapter_factory`).
- Routes: TV, monitor, audio -> `kz_ru/vd-sitemap.xml`; appliances -> `kz_ru/da-sitemap.xml`; smartphone -> the hubs `smartphones/all-smartphones/`, `smartphones/galaxy-a/`; tablet -> `tablets/all-tablets/`; other `SM-` rows (wearables) have no established route and request nothing. A blank or stub article requests nothing.
- Evidence levels stored as the page's match level: `full_sku` (the article in the page's markup or title), `code_in_page_text` (only in the visible text: never treated as an unconditionally exact variant), `base_model` (same base model, region/colour open: the phone `INS`/`ZA` vs `SKZ`/`DG`), `unknown`. A gallery is selected for the card only at `full_sku`.
- Documents: three facts kept apart (Russian by text; tied to the product by the official page: exact page / page with the code in text only / base-model page; what the text names: the exact catalog code / a family mask / only the code the page's link declares / nothing). The catalog model and the link's model are stored apart (`product_model` / `support_model`); no SC = VC (or any) code equality. A file without extractable text is not saved and goes to manual check.
- Dealer: the instruction stage runs before the dealer so it is asked only about what is still missing; DNS makes no request without a verified exact URL (none exists for Samsung: it yields the ready-to-ask request); a dealer page that is not an exact model-and-code match adds nothing; an added field has its own source; a difference from an official value is a `dealer_dispute` review and the official value stays.
- Status vs readiness: the job is `done` at `full_sku` with no conflicts (as for LG); readiness (`export_ready` / `export_ready_with_gaps` / `needs_verification` / `not_ready`) and its gaps are separate and are appended to the job message and exported on the sheet "Готовность Samsung".
- Normalization vocabulary grew by what Samsung pages folded into one name (display size vs product size, turntable, "image size" mode, door handle / doors / hinges / packaging qualifiers).

## Stage 27: owner decisions, planner, recorded evidence, batch 4
Report and evidence: `reports/source_census_2026-09-25_stage27/report.md`.

- Instructions (owner decision 1): a Russian instruction that names no model is accepted with the mark "связь с моделью подтверждена точной официальной страницей; точный код в PDF не назван" only on a page that shows the full article in its markup or title and prints the file's link, with a Russian-instruction text and no conflicting model. A PDF that names ANOTHER code (vacuum `SC18M21D0VG`, monitor `S24D300GAI`) is accepted only when the page's own data (`digitalData.product.model_name` beside `model_code`) declares that code as its model name for the catalog code; otherwise it stays for a person (`link_code_relation_unverified`). No SC = VC / LS = S rule. Code: `adapters/samsung.py` `instruction_acceptance`, `page_model_data`.
- Family mask (decision 2): accepted, always marked "точный код в PDF не назван" (document title, advisory gap `instruction_exact_code_not_in_pdf`, the export sheet).
- Photos (decision 3): never selected because the article merely occurs in the page's text. Selected: the whole gallery at `full_sku`; on a weaker page only photos whose OWN asset path names exactly the catalog code (`photo_variant_binding`); or photos a person confirms (`POST /products/{id}/photos`).
- Recorded evidence: `product_tool/config/samsung_recorded_documents.v1.json` holds the Stage 8.6 content assessment of the microwave manual; the adapter uses it for the same link and article and downloads nothing; the tie to the CURRENT page is read live.
- Planner: `samsung_official` is a working route with `url_basis = selected_one_per_category`; only the products listed under `selected_products` in `product_tool/config/coverage_planner.v1.json` are `ready_to_run` (20 of 1182 after the four Stage 29 memory products and the Stage 31 cable were added); the remaining 1162 rows stay in `manual_review` (1136 `not_selected_one_card_per_category`, 26 `seller_sku_not_a_manufacturer_code`). The executor has a Samsung factory with a refusing default transport.
- Batch 4 (real requests, declared first, 12 of 14 requests, no stop): dishwasher DW60M5050BB/WT (Russian file over the 40 MB cap, not obtained), dryer DV16DG8600BVLD, speaker MX-ST50B, robot vacuum VR50T95735W/EV (robot and station sizes/weights listed under the same names: a conflict left to a person). Recorded responses replay offline through the ordinary path (`tests/test_stage27_samsung_rules.py`).

## Stage 28: the dishwasher's Russian file, robot-vacuum devices, the route to the next categories
Report and evidence: `reports/source_census_2026-09-26_stage28/report.md`.

- Dishwasher: one declared attempt (1 request of 2 allowed, ceiling 60 MB) obtained the candidate Russian file (47 MB, 208 pages): Russian by text, exact code named, accepted. The assessment is recorded in `product_tool/config/samsung_recorded_documents.v1.json`; the adapter's default cap stays 40 MB. If such a candidate is not obtained or not read, the status is "кандидат на русскую инструкцию не проверен" (`instruction_russian_candidate_not_verified`), never "no Russian instruction"; a file in another language does not stand in for it (`instruction_only_non_russian_file_saved`).
- Devices of one product: a plain size / weight row belongs to a device only when a manual table that NAMES that device (a block headed by a series mask that covers the catalog code = the product itself; a block headed "Название <part>") carries the same value and no other table does, or when the page's own group title names the part. Row order is never evidence. The row keeps its value; its name gets the device in square brackets; unassigned rows keep the source's own name and value and open `samsung_device_values_check` (`adapters/samsung.py` `manual_device_tables`, `assign_devices`).
- Route: the official index `kz_ru/b2c-sitemap.xml` lists memory-sitemap.xml, im-sitemap.xml, assorted-sitemap.xml, vd-sitemap.xml, da-sitemap.xml. Memory and storage categories -> memory-sitemap; cables, watches, bands and earbuds -> im-sitemap (a page listed there is a current model). Seven of the 15 remaining categories have exact pages; eight have none in any observed sitemap.
- Readiness output has `gap_reasons`: the reason for every blocking and advisory gap; the export sheet shows them.

## Stage 30: brief guide, the page's own product data, the dealer link request (offline, no request)

- Brief guide (owner decision): a multilingual leaflet that is not a Russian instruction but carries a Russian section with instruction wording (`russian_section`: present, pages) is saved as a "Краткая памятка Samsung" with its pages and the mark "модель в тексте не названа". It is not a full Russian instruction and never closes the full-manual gap: the blocking gap is `instruction_full_russian_manual_missing`, the advisory `instruction_brief_guide_russian_section`. `instruction_language_not_russian` is said only when a file has no Russian section at all. A short Russian legal notice inside an English manual is not a brief guide.
- Variant by the page's own product data (owner decision): the fields `modelCode` / `shopSKU` / `apiChangeModelCode` / `originShopSku` / `data-model-code` / `data-shop-sku` of the exact page; when they declare exactly ONE code, equal to the catalog code (after normalization), the page has no other code in these fields and no differing JSON-LD sku, the variant is confirmed (`product_data_code`, strong) even if the markup and title do not show the code. A different code (the fridge's `/WT`, a phone's other colour) confirms nothing. Effect: the external SSD and the hob change from `code_in_page_text` to `full_sku`; the fridge and Galaxy A37 stay open.
- Dealer link request for Samsung (`samsung_pipeline.dealer_missing_fields`): "полная русская инструкция" counts as missing until a Russian instruction that is accepted by the rules is confirmed; a saved English file, a brief guide, a Russian file left to a person do not close it. Characteristics and photos are checked as before. The request is only text: no dealer request without a verified exact URL.
- Wearables: Watch7 is not a novelty; Fit 3 is not chosen (a page in the sitemap does not prove novelty). Group 5B was not run.
