# Очередь покрытия и адаптер HyperX: правила Stage 19

Дополнение к `docs/COVERAGE_QUEUE_V17.md` и `docs/COVERAGE_QUEUE_V18.md`. Отчёт этапа — `reports/source_census_2026-09-24_stage19/report.md`.

## Варианты страницы HyperX

Страница товара Shopify встраивает всю модель: `<script data-product-json>` перечисляет каждый вариант (id, sku, опции, штрихкод, главное медиа) и каждое медиа (id, alt, src), а JSON-LD `Product.offers` даёт по предложению на вариант со своим `url …?variant=<id>`. Верхний уровень JSON-LD, главное изображение и галерея по умолчанию описывают только вариант, выбранный на странице (и на странице по адресу `?variant=…` тоже: JSON-LD там всё равно называет вариант по умолчанию).

`adapters/structured_page.extract_shopify_product()` читает эти данные, **ничего не строя**. URL варианта считается наблюдавшимся и подтверждённым, только если предложение JSON-LD и встроенный JSON называют одинаковые `sku` и `id`, а `url` предложения ведёт на ту же страницу и несёт этот `id`.

`HyperXAdapter.parse_page(html, url, catalog_code=…)` сводит код каталога к одному варианту:

* `exact_variant` — если выбранный вариант страницы равен коду, **или** код есть как подтверждённая запись варианта (тогда `evidence` содержит `variant_source=in_page_variant_record`, вариант страницы по умолчанию назван, его значения не используются). Расхождение регионального кода (`#ABA` на странице, `#ACB` в каталоге) по-прежнему даёт `base_code_confirmed`.
* атрибуты варианта (`SKU`, `Variant name`, опции, `GTIN-12`) берутся из записи этого варианта;
* фото: у товара из одного варианта — все медиа; у нескольких — медиа с тегом `alt`, совпадающим с тегом главного изображения варианта (если тег у варианта уникален), иначе только главное изображение. Аннотированная инфографика (`annotated` в имени файла) идёт в группу `feature`, чужие варианты — в `excluded` с причиной. При неточной идентичности фото не заявляются;
* характеристики (таблица или «заголовок + список») и описание — общие для модели: `scope="model"`, список имён вариантных и общих атрибутов пишется в `evidence` (`attribute_scope=…`, `parse_attribute_scope()`), карточка исполнителя показывает его в `attribute_scope`. Схема БД не менялась (`jobs.py` — защищённый файл).

Повторяющаяся строка характеристик с другим значением в следующем **блоке** таблицы (заголовок открывает блок, даже повторяющийся) получает имя `<имя> (<метка блока>)`: `microphone`, если блок содержит свою строку «Element … microphone», иначе `<заголовок> #<номер>`. Повтор с другим значением внутри одного блока остаётся конфликтом на проверку. `<dl>` внутри контейнера `price` — цена, не характеристика.

## Журнал запросов и остановка host

`PolicyAwareFetcher` пишет `access_status` и `protection_status` каждого ответа. `stopped_hosts_from_fetch_log()` (используется fetcher, планировщиком и исполнителем) останавливает host при 401/403/429 **или** при `challenge_confirmed` / `browser_verification_required` с любым HTTP-статусом, включая 200. `challenge_suspected` записывается, но не останавливает (на hyperx.com эту оценку получает каждая обычная страница).

## Sitemap

`adapters/sitemap_urls.sitemap_locs()` читает `<loc>` как XML: `&amp;` → `&`, принимает только абсолютные http(s) URL, при усечённом теле возвращается к разбору текста с тем же декодированием. Ссылки sitemap не достраиваются и не переписываются.
