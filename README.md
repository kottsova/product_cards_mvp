# Product Cards MVP

Локальный инструмент для загрузки Excel и проверки товаров LG по нескольким источникам. Подтверждённые партии, доказательства источников, характеристики и ручные решения хранятся в SQLite. Длительный поиск выполняет отдельный worker. Правила Mechta и Sulpak применяются только к LG; другие бренды и n8n пока не подключены.

## Установка в Windows PowerShell

Откройте терминал в корне проекта:

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\product_tool\requirements.txt
```

## Запуск сайта и worker

В первом терминале:

```powershell
.\.venv\Scripts\python.exe -m uvicorn product_tool.web:create_app --factory --host 127.0.0.1 --port 8765
```

Во втором терминале, из того же каталога:

```powershell
.\.venv\Scripts\python.exe -m product_tool.worker
```

Откройте **http://localhost:8765/**. Оба процесса останавливаются через `Ctrl+C`. Сайт и worker используют `data/batches.sqlite3`. Если задана переменная `PRODUCT_CARDS_DATA_DIR`, её значение должно совпадать в обоих терминалах.

Для обработки одного задания и завершения worker:

```powershell
.\.venv\Scripts\python.exe -m product_tool.worker --once
```

## Сценарий LG

1. Загрузите `.xlsx`, проверьте лист и номера колонок, исправьте бренд, артикул или категорию и подтвердите партию.
2. Откройте товар LG и выберите этапы: **1 — источники, 2 — описание, 3 — характеристики, 4 — фото**.
3. Worker сначала ищет исходный полный артикул на LG. Если его нет, LG-specific normalizer выделяет базовую модель: для `S3WER.ALWPCOM` это `S3WER`.
4. После первой подтверждённой официальной страницы перебор LG прекращается. Затем исходный полный артикул проверяется на Sulpak и Mechta; базовая модель поставщикам не подставляется.
5. На странице товара отображаются найденные модели, доказательства, ссылки, ошибки загрузки, исходные значения каждого сайта и нормализованный итог.
6. При конфликте сотрудник может сохранить итог вручную. Решение имеет приоритет и остаётся после повторного запуска поиска.
7. На странице партии доступен Excel export с листами категорий, «Проверка источников» и «Источники».

Один HTTP-запрос ограничен 10 секундами и одной повторной попыткой при временной сетевой ошибке. Бюджеты: официальный LG — 20 секунд, fallback LG — 30 секунд, весь поиск одного товара — 60 секунд. Число кандидатов ограничено.

## Статусы

Уровень совпадения отдельного источника:

- `full_sku` — в видимом тексте найден полный входной артикул;
- `base_model` — официальный LG подтвердил только базовую модель;
- `mismatch` — страница загрузилась, но нужное обозначение не подтверждено;
- `unknown` — источник не удалось проверить, в том числе из-за блокировки или таймаута.

Итог идентификации показывает, найден ли полный артикул на LG, подтверждён ли он Sulpak, Mechta или обоими поставщиками, либо требуется проверка. Для характеристики используются статусы:

- `confirmed_two_suppliers` — оба поставщика подтвердили полный SKU и совпали;
- `confirmed_one_supplier` — полный SKU и значение подтвердил один поставщик;
- `matched` — нормализованные значения совпали;
- `needs_review` — поставщики расходятся или подтверждения недостаточно;
- `manual` — сотрудник сохранил итог вручную.

Размеры сравниваются с учётом порядка осей, единицы приводятся к общему виду, логические значения — к `true/false`. Масса товара и масса с упаковкой хранятся как разные характеристики. Все исходные названия и значения остаются в базе вместе с источником.

## Данные и безопасность

Загруженные книги находятся в `data/uploads/`, база — в `data/batches.sqlite3`. Excel, SQLite, выгрузки, HTML ответов сайтов, `.env`, `credentials.json` и ключи исключены из Git. Адаптеры не используют старую папку, Google Sheets, фиксированный ID таблицы или диск `A:` во время работы приложения.

## Проверки

Автономные проверки используют HTML fixture-строки и временные Excel/SQLite, интернет им не нужен:

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
.\.venv\Scripts\python.exe -m py_compile product_tool\*.py product_tool\adapters\*.py
```

Живая проверка сайтов выполняется отдельно и не входит в обычный набор тестов, потому что сайты могут менять разметку или блокировать автоматические запросы.

## Состав проекта

- `product_tool/importer.py` — чтение Excel; дополнительные сведения в [product_tool/README.md](product_tool/README.md).
- `product_tool/web.py` — загрузка, подтверждение, страницы товара и export.
- `product_tool/jobs.py` — очередь и таблицы SQLite для источников, фактов, итогов и ручных решений.
- `product_tool/worker.py` — ограниченный по времени фоновый сценарий LG.
- `product_tool/adapters/lg.py` — официальный LG и LG-specific правила артикула.
- `product_tool/adapters/sulpak.py`, `product_tool/adapters/mechta.py` — доверенные fallback-источники LG.
- `product_tool/normalization.py`, `product_tool/resolution.py` — общие правила нормализации и разрешения значений.
- `product_tool/exporter.py` — Excel export результатов и аудита источников.
- `docs/` — архитектура и рабочие сценарии.
