# Product Cards MVP

Локальное FastAPI-приложение для загрузки Excel, проверки товаров LG по нескольким источникам и ручного подтверждения результата. Партии, источники, исходные факты, решения, документы и выбор фотографий хранятся в SQLite. Правило Sulpak применяется только к LG.

## Установка и запуск в Windows PowerShell

```powershell
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r .\product_tool\requirements.txt
```

Запуск сайта и обработки заданий в одном терминале:

```powershell
.\.venv\Scripts\python.exe -m uvicorn product_tool.web:create_app --factory --host 127.0.0.1 --port 8765
```

Откройте **http://localhost:8765/**. Обработка очереди запускается вместе с сайтом и использует тот же `data/batches.sqlite3`. Уже ожидающие задания продолжатся после перезапуска сайта.

## Этапы LG

1. **Источники и модель** — полный входной артикул, базовая модель, LG Казахстан, LG Россия, затем Sulpak для полного артикула.
2. **Описание** — содержательные блоки каждой официальной страницы отдельно.
3. **Характеристики** — исходные факты каждого источника, нормализация и итог.
4. **Фотографии** — кандидаты товарной галереи, особенности и исключённые изображения; пользователь сохраняет выбор ссылок.
5. **Видео** — номер зарезервирован.
6. **Инструкции** — только русские официальные документы LG по доказанной на товарной странице связи с моделью поддержки.

Один HTTP-запрос ограничен 10 секундами и одной повторной попыткой. Официальные регионы делят бюджет около 20 секунд, fallback LG — 30 секунд, общий поиск источников товара — 60 секунд. Недоступный регион или поставщик сохраняется с ошибкой и не считается успехом.

## Статусы характеристик

- **Найдено только у базовой модели LG** (`official_base_only`) — значение есть только у официальной базовой модели, полного SKU оно не подтверждает и конфликтом не является.
- **Подтверждено одним поставщиком** — значение полного SKU подтвердил Sulpak.
- **Подтверждено двумя поставщиками** — сохранено в коде на случай появления второго доверенного поставщика. Сейчас доверенный поставщик один (Sulpak, только для LG), поэтому этот статус не возникает; дилерские страницы вне этого списка значения не подтверждают.
- **Различие официальных регионов** — LG Казахстан и LG Россия дали разные нормализованные значения.
- **Нужна проверка** — минимум два источника дали разные значения.
- **Выбрано вручную** — решение сотрудника; оно имеет приоритет после повторного запуска.

Страница задания отдельно показывает число реальных конфликтов, характеристик только от базовой модели и значений, подтверждённых поставщиком полного артикула. В интерфейсе и Excel используются русские названия и значения: `Да/Нет`, `кг`, `мм`, `об/мин`, размеры в порядке `Ш × В × Г`.

## Инструкции

Worker сначала извлекает официальную ссылку поддержки из HTML товарной страницы LG Россия. Для `S3WER` допустима связанная модель `S3RERB`, потому что связь опубликована самим LG. Сохраняются только русские документы, их дата, размер, модель поддержки и прямая ссылка `gscs-b2c.lge.com`. PDF не скачивается. Повторный запуск этапа 6 заменяет список без дублей.

## Фотографии

Официальная товарная галерея выбирается по умолчанию. Инфографика остаётся отдельной группой. Фото поставщиков по умолчанию не выбираются. Sulpak фильтрует баннеры, логотипы и служебные изображения; варианты `_160` и `_320` объединяются с оригиналом. Ручной выбор сохраняется по `asset_key` после повторного этапа 4. Изображения не скачиваются и не обрабатываются.

## Excel export

На странице партии доступна выгрузка с:

- листами категорий с итоговыми русскими значениями;
- листом «Проверка источников»;
- листом «Источники»;
- листом «Инструкции»;
- листом «Фотографии» только с выбранными ссылками.

## Очередь покрытия каталога (офлайн)

```powershell
.\.venv\Scripts\python.exe -m product_tool.coverage plan --out reports\<каталог-вывода> --print-summary
.\.venv\Scripts\python.exe -m product_tool.coverage delta --before <до>\coverage_units.jsonl --after <после>\coverage_units.jsonl
```

Планировщик читает каталог только на чтение, сети не касается и для каждого уникального товара выдаёт один статус: готов к запуску, адаптер есть — URL нет, маршрут известен — адаптера нет, нужен fixture Product page, host заблокирован, конфликт identity/варианта, ручная проверка. Fixture Product page подтверждает только ту категорию, host, рынок и шаблон страницы, которые реально наблюдались, а не весь бренд; повтор артикула у разных категорий или брендов — риск для проверки по названию и модели, а не конфликт сам по себе. Описание и критерии готовности адаптеров — `docs/COVERAGE_QUEUE_V17.md`, `docs/COVERAGE_QUEUE_V18.md`; варианты страниц HyperX, остановка host по challenge и sitemap — `docs/COVERAGE_QUEUE_V19.md`. Сетевые запросы LG (адаптеры по умолчанию) идут через policy-aware fetch с журналом `lg_fetch_log.json` — `docs/LG_POLICY_FETCH_V20.md`. Статус задания и готовность карточки к выгрузке разделены (`product_tool/readiness.py`), физические величины с разным смыслом получают разные имена, страницы LG Россия берутся из наблюдаемой карты сайта — `docs/LG_STAGE21_RULES.md`. Инструкции LG Россия (страница поддержки → PDF → подтверждение по тексту файла, язык по тексту) и фото LG Россия — `docs/LG_STAGE22_RULES.md`. Ответы владельца (метка `_KZ`/`_SU`, страница поддержки, расхождения KZ/RU, инструкция без модели в тексте) и рабочее правило «одна карточка на категорию, без массовых прогонов» — `docs/LG_STAGE23_RULES.md`. Samsung: категории, правила выбора одного товара на категорию и первая партия — `docs/SAMSUNG_BATCH1_FINDINGS.md` (там же ограниченный адаптер Samsung `product_tool/adapters/samsung.py`, поправка этапа 25 и подключение к `run_once()` на этапе 26: `product_tool/adapters/samsung_source.py`, `product_tool/samsung_pipeline.py`, `product_tool/samsung_readiness.py`; запросы идут через policy-aware fetch с журналом `samsung_fetch_log.json`; этап 27: решения владельца по инструкциям и фото, Samsung в планировщике по одному выбранному товару на категорию, партия 4).

## Данные и безопасность

`data/`, загруженные Excel, SQLite, сохранённые HTML, изображения, PDF, выгрузки, `.env`, `credentials.json` и ключи исключены из Git. Приложение не использует старый парсер, Google Sheets или фиксированные пути к диску `A:`.

## Проверки

```powershell
.\.venv\Scripts\python.exe -m tests -v
.\.venv\Scripts\python.exe -m py_compile product_tool\*.py product_tool\adapters\*.py
```

Тесты используют встроенные HTML fixtures и временные SQLite/Excel без интернета. `python -m tests` (а также `unittest discover -s tests -t .` и `unittest tests.<модуль>`) включает запрет реального HTTP/DNS до загрузки любого тестового модуля. Прежняя команда `unittest discover -s tests` без `-t .` пакет `tests` не импортирует: запрет там держится только на том, что `test_000_network_safety.py` загружается первым, поэтому при выборе части файлов (`-p`) он не гарантирован. Подробности — `docs/COVERAGE_QUEUE_V17.md`. Живая проверка выполняется отдельно, поскольку сайты могут менять HTML или блокировать запросы.
